**数值与绘图数据链核对通过，但 C→D 的 JSON 载入存在一个可复现的接口问题，不能把端到端交接标为全部通过。**

1. A 独立重算全部 25 组，提交 CSV 数值最大差约 4.26e-14；另按预算定义逐状态重算 W，最优 CVaR 与 C 实际策略评价最大差约 2.13e-14。
2. 重跑 C 的整个 E2，全部 25 行 CSV 最大差约 7.11e-15。导出 JSON 的策略表、参数、起始预算与原文件完全相同；mean_value 最大差约 7.11e-15，cvar 无差异。
3. F2 的路线、风险区域、161 个 PMF 数据点与策略／CSV 一致；F3 五个面板中 25 个红点、25 个蓝点及 α 标注与提交 CSV 一致。
4. 当前 poster JSON 在坐标类型规范化后可重建相同环境；预算策略与重新求解一致，起始阈值 24。当前 mean_policy 与 C 真正的 fallback 完全一致（0 个状态不同），因此当前未单独导出 fallback 没有造成数值差异。
5. 尾部补全可对上，在明显非零 overflow 的低 cutoff 下也对上，而非仅依赖 cutoff=160 的极小残差。

## A 的独立计算方式

没有调用 C 的尾部计算器建立标准答案。A 自己组装非终点状态线性方程，求同一 fallback 的期望剩余代价；自己按 (state,spent) 向前传播概率并记录首次越界质量。越界到达 (s,z) 的贡献为 mass×(z+J_fallback(s))。从最坏概率往回积分，算出含尾部的 CVaR。

独立预算检查按 W 的定义逐状态、逐动作求和，边界使用已经独立线性评价并与 VI 一致的期望最优值；对每个 p 计算 0–128 层，再对各 α 搜索阈值。全部最优值小于 129，可排除更大整数阈值带来改进。这里是数值交叉检查，不声称符号精确或对浮点误差的形式化证明。

## 发现的问题与交接建议

### P1：导出 JSON 不能按当前 D 入口直接载入

复现：`data=json.load(...)` 后执行 `make_grid(**data['grid'])`，得到 `ValueError: the goal must have no actions`。

原因：JSON 将 start、goal 等坐标写为数组，读取后成为 list。`make_grid` 在构建终点时比较 `(r,c)==goal`，tuple 与 list 不等，因此终点被当成普通状态赋予了动作。D 的 `experiments/run_dist_demo.py:114` 正好按此路径载入。

建议修复：在 JSON 读取边界，把 start、goal、zone_rows、zone_cols 规范为 tuple；或在共享 `make_grid` 入口统一处理。仅把导出前的值写成 tuple 不能解决，因为 JSON 仍会把它转成数组。修复后加一个“导出→json.load→重建环境→执行策略”的端到端回归。

这是可复现的交接缺陷，不推翻已经存在的 C 数值或 F2/F3。

### D 的旧导出入口还未使用尾部补全

即使修好坐标，`run_dist_demo.export` 仍在任何 overflow 非零时留空 mean/var/cvar。对当前 p=0.1、cutoff=160，两种策略的 overflow 都非零；这与旧风险函数的保守设计一致，但意味着它不能直接导出 C 当前含尾部的指标。

建议 C/D 集成时使用 C 的 `evaluate_distribution`（明确 fallback 和切换阈值），继续保存原始 overflow 和 tail_first_moment；不要修改为归一化后直接计算，也不要把留空误称为算错。本次 C 自己的 CSV 和图不受旧导出入口影响。

### 展示层面的改进

- F3 的 p=0 和 p=0.05 面板 α 标注较密，有重叠，建议调整偏移或改用注释表。这是可读性问题，不是数据不一致。
- F3 不应称为同一个风险水平下的 Pareto 前沿；不同点采用不同 α，C 的现有图注已说明，应保留。
- F2 只显示 0–90 分钟；超过 90 的质量分别约 9.12e-7 和 2.73e-8。现有报告图注说明了视窗与传播上限，整合 poster 时应保留该说明。
- 建议 JSON 未来显式保存 `fallback`，不要永久假定它与 `mean_policy` 相同；本次已经实测两者相同，不把此建议当作当前数值错误。
